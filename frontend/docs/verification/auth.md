# 注册、登录、登出与用户隔离验收

本次只修改 backend 与 frontend，认证通过项目中间件、路由和工作区扩展接入，没有修改 AgentScope 框架源码。

## 自动验证

- 后端 55 项测试通过，覆盖认证、Z.ai、知识库、SkillHub、MCPHub 和 OFDM 原有功能。
- 认证测试覆盖匿名访问拒绝、伪造身份头、Cookie 会话、CSRF、来源校验、密码哈希、登录轮换、退出后旧会话失效、跨用户凭据与工作区隔离、旧下载 Token 越权拒绝及旧数据绑定。
- 知识库验证包含 TXT、PDF、DOCX、XLS、XLSX、PPTX 文档解析、向量落盘及独立进程重新加载；另验证了登录后的上传、索引、检索链路与其他用户访问拒绝。嵌入 API 使用离线替身，不代表真实厂商 Key 已通过调用测试。
- SkillHub 和 MCPHub 保留全部已接入来源，现有来源适配、安装及同名资源身份判断测试通过。
- 前端 19 项测试通过；TypeScript、改动文件 ESLint 与 Vite 生产构建通过。
- 真实 Redis 已验证登录会话写入、查询、撤销与原子限流计数。

## 浏览器验证

使用独立前端端口、临时数据库和两个临时账号完成以下操作，未创建正式账号：

1. 注册账号 A 并登录，刷新后仍恢复该账号身份。
2. 账号 A 创建的智能体可见。
3. 退出 A，注册并登录 B，B 看不到 A 的智能体。
4. 退出 B 后访问凭据页面，返回登录页。
5. 正式页面已显示登录入口，截图见 [auth-login.jpg](./auth-login.jpg)。

## 现有数据与启用结果

当前后端已重启并启用认证：`GET /auth/health` 返回 200，匿名伪造 `X-User-ID` 访问业务接口返回 401。

重启前后的 14 条现有业务记录内容一致，原文档文件与工作区目录保留。新账号不会自动认领旧用户名的数据；请先注册账号，在创建新业务资源前，按 backend/README.md 的「保留并绑定旧数据」执行管理员绑定，完成后重新登录。

当前隔离覆盖身份认证、业务资源与文件接口。本地 Shell 和本机 MCP 仍使用宿主机权限；向不可信用户开放执行工具时，还需要执行环境沙箱。
